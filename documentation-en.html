How to get the files on your computer

Option 1 – Download everything as a ZIP (easiest)

  1. Open https://github.com/botelectro9/Text-Scrambler
  2. Click the green Code button, then Download ZIP.
  3. Unzip the archive.
  4. Double-click text-scrambler-en.html (or texte-brouille-fr.html) to open it in your browser.

Option 2 – Download a single file

  1. In the repository, click the file name (for example text-scrambler-en.html).
  2. Click the Download raw file button (down-arrow icon, top right of the file view).
  3. Check that the saved file ends with .html. Some browsers add .txt (for example text-scrambler-en.html.txt) or save it without an extension. If so, rename it so it ends with .html. On Windows, turn on View → File name extensions in File Explorer to see the real extension; on macOS, use Get Info → Name & Extension.
  4. Open the file in your browser.
Don't use "Save page as" on the GitHub file view: it saves GitHub's page, not the tool.

Option 3 – With Git

git clone https://github.com/botelectro9/Text-Scrambler.git
cd Text-Scrambler

Then open one of the .html files in your browser.

About

Scrambled Text is a single-file HTML/JavaScript page that turns a piece of text into an image. Letters are distorted and the image is covered with noise, decoy characters, strike-through lines and a watermark, so a human can still read it while automatic text recognition (OCR) has a much harder time.

Features

  • Each character gets its own font, size, rotation, skew and color.
  • A wave distortion is applied to the whole image.
  • Faint decoy letters are scattered in the background.
  • Curved lines cross the text, and small arcs are drawn over some letters.
  • A repeated diagonal watermark with customizable text.
  • Pixel noise and colored speckles.
  • Choice of image resolution (presets for phone, tablet and computer, or custom), with the text centered and shrunk automatically if it does not fit.
  • Another variant button to get a different random layout of the same text.
  • Export as PNG (download or copy to clipboard).
  • Animations exported as GIF or video (WebM): fragmented letters, optionally moving so that stacking the frames does not rebuild them, with dynamic perturbations that change every frame.
  • Light and dark theme, works on desktop and mobile.

Installation

No installation, build step or server needed. Everything runs in the browser.

  1. Download text-scrambler-en.html (see Download).
  2. Open it in a modern browser (Chrome, Firefox, Safari, Edge).

You can also put the file on any static web host (GitHub Pages, Netlify, your own server).

Usage

  1. Type or paste your text in the Your text field. Line breaks are kept; long lines wrap automatically.
  2. Adjust the settings:

Animations

A still image can be read by anything that looks at one picture. An animation can spread the text over time: each frame on its own shows little or nothing, and the human eye puts the frames together.

Choose the animation in the Output list:

  • Animation · fragments: the scrambled text is shown, but each frame shows only part of every letter, picked at random. The eye fills in the gaps while the animation plays. A tool that averages the frames rebuilds the text, though.
  • Animation · fragments + motion: the same fragments, but every word also moves along its own small ellipse, with its own starting point and direction, one full turn per loop. The eye follows the words and still puts the fragments together, while averaging the frames only gives blurred smudges where the words were. Because each word moves differently, aligning all the frames with a single shift does not work either. Some room is kept around the text for the motion, so the text can be slightly smaller.
  • Animation · complementary fragments + motion: built against AI models, which often look at a single frame (usually the first one). The first frame shows no text at all. In the other frames, the cells of every word are split into fixed groups shown in turn, so each frame holds only 1/2, 1/3 or 1/4 of every letter, while a few consecutive frames together show all of it. The groups move with their word, so the coverage holds during the motion. The Groups slider (2–8, default 3) sets how many groups there are: each frame shows 1/Groups of every letter. With Random cuts checked (the default), a new cutting pattern is drawn at the start of every cycle, so a letter is not cut the same way from one cycle to the next; within a cycle, the groups still cover the whole letter.

Dynamic perturbations are elements that change every frame. In a single frame they look like part of the message, but they do not last, so the eye discards them while a tool analysing one frame does not:

  • Text-like decoy letters, dark and as big as the text, each shown for a single frame (their number and opacity grow with the setting), when Decoy letters is checked; the crossing lines are redrawn at new positions every frame, when Crossing lines is checked; pixel noise is new in every frame.

These are not adversarial perturbations in the machine-learning sense. Those are computed against one specific model, rarely fool other models, and usually do not survive the compression applied by social networks.

Exports

  • GIF: works in every browser and is encoded directly in the page (252-colour palette, infinite loop). Noisy animations make large files: lower Noise, the number of frames or the resolution if needed.
  • Video: recorded in real time with the browser's MediaRecorder (WebM VP9 or VP8; MP4 on Safari), looped to last at least 6 seconds, at a high bitrate so the noise and fragments are not smeared. Keep the tab visible while it records. Much lighter than the GIF.
  • Animations are limited to 1080 px on their longest side to keep memory use and file sizes reasonable; the status line says when the size was reduced.

Tips for animations

  • If the text is hard to read, lower Perturbations, raise Fragments (up to 100 %) or raise Size.
  • Flickering animations can be uncomfortable, and are a risk for people with photosensitive epilepsy. Avoid very high frame rates with strong perturbations.

Recommended settings

  • Default (5 / 5 / 4): good balance between readability and protection.
  • Stronger (7–8 / 6 / 7): harder for OCR. Check that the text is still easy for you to read.
  • Shorter texts and larger sizes stay more readable when distortion is high.

Tips for large fonts

Rotation and skew are angles, so they scale with the letters. The wave, the vertical jitter and the thickness of the crossing lines are fixed in pixels, so they disturb big letters proportionally less.

  • With a large size, raise Distortion (7–9) and Noise (6–8) to keep the same level of protection.
  • Decoy letters and the watermark grow with the text. Raise Decoys to keep the background covered, then check that the text stays readable.
  • If the text does not fit, the size is reduced automatically and the status line says so. Shorten the text or pick a larger resolution instead of pushing the size further.
  • To get bigger text on screen, a larger resolution with a moderate size often works better than a huge size on a small image.

Maximizing OCR resistance

  • Check Watermark, Decoy letters and Crossing lines (all off by default), start from Distortion 7–9 / Noise 6–8 / Decoys 6–8, then lower whatever hurts readability.
  • Enable the watermark. Extra text spread over the image gives OCR more false characters to deal with.
  • Prefer short texts. Split a long message into several images: OCR has less context to guess the missing words.
  • Click Another variant several times and test each image with an OCR app (for example Google Lens or your phone's text recognition). Keep the one it reads worst.
  • Where animations are accepted, prefer complementary fragments + motion: the first frame shows no text, every other frame shows only part of each letter, and averaging the frames does not rebuild them. Raise Groups (4 or 5), keeping Random cuts checked, to show less, and less predictably, in each frame, as long as you can still read the animation.
  • Do not repeat the text in the caption, alt text or hashtags: that would make the image pointless for this purpose.
  • Remember the limits below: recent AI vision models can read text that defeats classic OCR.

Output

  • Size: chosen in the Resolution list (default 1080×1350, a 4:5 social-network feed format). Animations are limited to 1080 px on their longest side.
  • The text block is centered horizontally and vertically.
  • Format: PNG for still images, GIF or video (WebM, or MP4 on Safari) for animations.

Limitations

  • This makes classic OCR much less reliable, but recent AI vision models can often read fairly distorted text. There is no guarantee the content will go undetected.
  • Platforms decide on visibility using many other signals (reports, account behavior, engagement, captions, hashtags). An image alone does not prevent a shadowban.
  • Heavily distorted images are harder to read for people with visual impairments and are invisible to screen readers. Consider adding a description when the context allows it.
  • Fonts used (Georgia, Courier New, Verdana, etc.) are system fonts; the rendering may vary slightly between operating systems.
  • Animations protect against tools that look at one frame at a time. A tool that combines several frames can recover the text: averaging the frames rebuilds the letters of the fragments animation. The fragments + motion animation resists plain averaging, but a tool that tracks each word separately and realigns it before stacking could still rebuild the text. The same goes for the complementary mode, although each of its frames holds less of every letter.

How it works

The page draws on an HTML <canvas>:

  1. A tinted background with random color gradients.
  2. Decoy characters at low opacity.
  3. The text, character by character, with random transforms.
  4. A sine-wave pixel displacement over the whole image.
  5. Crossing Bézier curves and arcs over glyphs.
  6. A rotated, repeated watermark.
  7. Per-pixel noise and speckles.

The result is converted to a PNG with canvas.toDataURL(). A seeded pseudo-random generator (mulberry32) drives all the randomness.

Animations reuse the same layers:

  • The background and the text are drawn on separate layers with the same wave, then each frame combines the background, a random subset of small cells of the text layer, the single-frame decoys, the lines, arcs and watermark, and fresh pixel noise.
  • With motion, the text layer is redrawn every frame with each word shifted along its ellipse. The random generator is replayed from the same point every frame, so each glyph keeps its font, colour and tilt while it moves.
  • In the complementary mode, each word is drawn alone once. In every frame, the mask of the current group is applied in the word's resting coordinates, then the piece is moved along the word's ellipse and passed through the wave. With random cuts, new masks are drawn at the start of every cycle.
  • The GIF encoder (LZW compression, fixed colour palette) is included in the page; the video uses canvas.captureStream() and MediaRecorder.

Customization

Inside the <script> block you can edit:

  • FONTS: the list of fonts picked for each character.
  • DECOYS: the characters used as background decoys.
  • The <option> entries of the res list: the preset resolutions (value WIDTHxHEIGHT).
  • BASE_SIDE: the short side, in pixels, that the Size value refers to (default 1080). On larger images the font is scaled up in proportion.
  • ANIM_MAX_SIDE: the longest side of animations (default 1080).
  • MOTION_RADIUS_RATIO: the horizontal radius of the word orbits in the fragments + motion animation, as a share of the font size (default 0.35; the vertical radius is half of it).
  • VIDEO_BITRATE and VIDEO_MIN_SECONDS: the video bitrate (default 12 Mbit/s) and minimum duration (default 6 s).
